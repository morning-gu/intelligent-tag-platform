# 标签生产提示词样本

平台按一次生产任务提交采集样本，涵盖开放生成的各个模型阶段和生产分流后的质量评估。每个阶段记录该批第一个成功返回的模型调用。一批选多部影片、生成多轮、评估拆批或发生解析重试时，每个阶段最多写一套文件。多部影片并发时，以先返回并被采集的调用为准，各阶段可能采到不同影片。手工重试任务或影片评估按新批次采集。

| 文件名前缀 | 阶段 |
| --- | --- |
| `generation` | 候选生成，含影片内容、关键帧及此次请求使用的库词和目录提示。 |
| `judge` | Judge 审核，含合并后的候选、影片文本和判定要求。 |
| `verify` | 疑似同义复核，含候选词与匹配库词。 |
| `description` | 通用释义补写，含需要补写的候选词及目录。 |
| `quality` | 分流后标签质量评估，包含影片材料及当次评估的待审和直挂快照标签。`tag-quality-v2` 对内容相关性、语义准确性和标签价值独立评分。模板同时展示关键帧与纯文本两种请求。 |

- `*_template.json` 由实际提示词构造代码填入 `{{占位符}}` 生成。生成模板展示可选提示块和关键帧结构，缺少目录提示时的末段指令见 `instructions_without_directory_hint`。有解析重试提示的阶段在 `retry_suffix` 中列出追加文字。
- `*_example.json` 的 `messages` 是该次调用的完整输入，包括图片的原始 data URL。`run_id` 和 `model` 用于识别样本及模型，`model: "mock-1"` 表示本地 Mock 调用。
- `*_result.txt` 保存该次模型返回的正文，保留原始格式，可能包含模型输出的 Markdown 或无效 JSON。

质量评估只采集该批第一个通过响应校验的调用。响应需完整返回本次请求中每个标签的三维评分，且标签 ID 与请求一一对应。遇到输出截断后拆批时，保存的是首个完整子批次的请求与原始响应，全部评分可在生产任务详情查看。

同名文件在下一次采集到该阶段时覆盖。该批没有可采集的响应时，保留上一次的样本。例如所有候选都已有合格释义时，该批沿用上一套 `description` 样本。各阶段的样本来源可通过 `run_id` 核对。

默认写入服务工作目录下的 `docs/open-tag-prompts`。可用 `TAGPLT_MTG_PROMPT_SAMPLE_DIR` 指定其他可写目录，设为空则关闭采集。写入失败会记服务日志，生成和评估继续执行。样本可能包含影片素材或内部标签词表，默认路径下的运行文件由 Git 忽略。
