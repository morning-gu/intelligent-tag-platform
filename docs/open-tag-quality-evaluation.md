# 生成标签自动质量评估功能

> **现状说明**：原内嵌在「生产任务」中的附带标签质量评估已退役并迁入独立的**开放评测（Open Eval）**模块（详见 [`docs/eval.md`](eval.md) §5）。本文 **§2.2–§2.5 的三维 0–4 五档评分口径**现由开放评测独立盲评提示词 `open-review-v10`（`src/tagplatform/capabilities/prompts/open_review.py`）持续沿用；§1、§3.2–§5 记录的是早期生产任务附带评估的流程设计，留作历史参考。

## 1. 功能位置与运行方式（历史设计）

生产任务展开后，可在「标签产出与评分」卡片右上方打开「评分标准」，查看五档的判定门槛。

在现有影视标签生产任务中增加「标签质量评估」环节。触发时机是：**某部影片的标签生成流程全部结束，最终标签完成生产分流之后**。生产分流包括进入待审核队列，以及满足条件后直接挂载；两类标签都参与评估。

执行流程：

1. 现有生成流程完成，产出该影片最终标签。
2. 标签按现有规则分流：需要人工审核的进入审核队列，满足条件的直接挂载。
3. 两类标签都进入本次质量评估范围，后台自动启动该影片的标签质量评估。
4. 评估完成后保存逐标签结果，并更新影片级指标和任务级汇总指标。

评估作为独立的后台子流程运行。生成任务完成、标签进入人工审核队列或直接挂载，以及人工审核操作，都不需要等待评估结束。评估状态单独记录和展示。

建议按影片触发评估：一部影片的最终标签完成生产分流后即可开始评估；任务内各影片的结果逐步完成，任务级指标随之更新。

评估针对**本次生产流程最终产出的标签结果快照**，同时包含进入人工审核队列的标签和满足条件直接挂载的标签。人工审核之后对待审核标签进行的通过、驳回或修改，仍按现有审核流程处理；评估结果对应的是生产分流时的那一版标签。

## 2. 评估输入与评价维度

### 2.1 输入内容

评估时使用该影片本次生成任务对应的影视内容，以及本次生产流程产出的最终标签，包括进入待审核队列和直接挂载的标签。

影视内容尽量沿用生成阶段已有的信息，包括影片摘要、人物、场景描述、台词和关键帧。标签侧使用最终标签名称、最终释义，以及现有数据中可用的层级和维度信息。

当前生成模板中：
- `desc` 是标签本身的通用释义，用于解释标签概念。
- `reason` 是生成模型给出的本片内容依据。

评估时，语义准确性主要依据标签名称及最终 `desc` 判断；内容相关性则应回到影片原始内容中寻找依据，不能仅凭生成模型提供的 `reason` 判定相关。

如果标签涉及画面风格、镜头语言等视觉信息，应尽量将生成阶段使用的关键帧一并提供给评估模型。缺少必要视觉材料时，允许将该项评为「无法判断」。

具体输入字段和数据映射以仓库中实际的待审核标签结构、影片内容结构为准，由实现时结合现有代码确定；本功能不另行定义生成结果的 JSON 格式。

### 2.2 五档判定方式

现行开放评测盲评提示词 `open-review-v10`（沿袭原 `tag-quality-v5` 口径）对三个维度分别打 0–4 分。按 0 到 4 的顺序检查，命中第一档即停。`level` 决定用途和取证范围。评级理由写出命中的门槛以及没有升档的具体原因。如果缺少必要材料，且无法区分相邻档，记为 `null`。只要已有证据足以判断缺陷，就按对应档评分。历史 `tag-quality-v4` 也使用五档量表，其全片标签价值按名称具体性判断是否具备升至 3–4 分的条件。

### 2.3 内容相关性

检查名称的核心概念和每一个会改变含义的限定。场景词只用来源场景的材料。人物词对应指定人物。影片词的 3–4 分须有至少两个独立剧情或视听段落支撑。一个即时问题的发生、应对和解决合计一个事件，例如被困、找出口和脱困。相邻场景重复描述同一次转场时也只计一个段落。

| 分数 | 判定门槛 |
|---|---|
| 0 | 核心概念或任一必要限定有直接反证，或可核查材料中没有相关对象、事件与属性。 |
| 1 | 找得到相关对象、场所或话题，核心动作、属性或关系缺乏明确记录及可推导依据。 |
| 2 | 核心概念有明确依据，但缺少至少一个必要限定，或者全片级概括只由同一事件支撑。 |
| 3 | 核心与全部必要限定均能获证，覆盖范围符合层级，需要借材料中的细节完成一步推理。 |
| 4 | 核心与全部必要限定均能从场景描述、台词、画面或人物材料直接定位，覆盖范围符合层级。 |

例如材料明确记载 AI 唱歌及拔除记忆模块，却没有交代切断电源，「AI断电歌唱」的相关性落在 2 档。如果材料明确排除了断电，则落在 0 档。如果核心与限定都能找到，但要从行为推断人物情绪，则落在 3 档。

### 2.4 语义准确性

分别判断名称和最终释义会把哪些实例纳入，缺少最终释义记为无法判断。

| 分数 | 判定门槛 |
|---|---|
| 0 | 名称与释义的核心概念相反，或没有可对应的概念。 |
| 1 | 共享话题，但中心指代或类别不同，例如把音乐类型定义成以该音乐为核心的节目。 |
| 2 | 中心概念相同，但适用边界不同。必须举一个只符合名称或只符合释义的实例。 |
| 3 | 适用边界一致，但释义仅改写名称，或只给了本片例子。 |
| 4 | 适用边界一致，且释义给出对象及可跨片判断的区分条件。 |

例如「国际象棋对弈」也包含两个人下棋。若释义仅指人机对弈，两个人下棋就是判 2 档的反例。

### 2.5 标签价值

先读名称本身。释义和证据用于核查词义与筛选条件，名称独立传达的信息才计入价值。

| 分数 | 场景搜索 | 全片展示 | 人物 |
|---|---|---|---|
| 0 | 名称脱离剧情无法解释成可检索的内容。 | 名称依赖本片剧情才能理解，无法独立表达影片属性。 | 名称脱离剧情无法解释成独立属性。 |
| 1 | 名称可读，但只表达有无、编号或泛泛评价，无法排除常见无关片段。 | 只传达属性的有无、泛泛评价或单一局部动作，提供的全片信息很有限。 | 只表达有无、编号或泛泛评价，无法筛掉常见无关项。 |
| 2 | 名称写出了普通事件类目，尚无额外筛选限定，或表达须改词序、补主体。 | 只给出宽泛的选片方向，观众难以形成清楚的题材、叙事或视听预期，或名称需要改写。 | 只能筛到泛类目，或名称需要改写。 |
| 3 | 按自然词序写出事件或视听现象，恰有一个可核实的独立限定。 | 名称自然，准确传达有据的次要属性，补充观众的观影预期。 | 名称自然，描述有据的具体次要属性。 |
| 4 | 按自然词序写出事件或视听现象，至少有两个可核实且独立的限定。 | 名称自然，准确传达核心题材、主要叙事类型、主线、主要冲突或主导视听体验。写明观影预期及至少两个独立段落如何各自支撑它。 | 名称自然，直接表达主线、主要冲突、主导视听风格或人物贯穿剧情的身份与行为。说明它改变哪一项预期，并指出至少两个独立段落如何各自体现这一属性。 |

可计的场景限定包括参与者、对象、地点、时间条件、动作方式、可识别的视听细节。动作本义已经包含的对象、通用参与者和同义词不再单独计数。比如「国际象棋对弈」是事件类目，记 2 分。加上「AI」限定的「AI下国际象棋」是 3 分。「AI拒开舱门」的两个限定是 AI 与舱门，分别排除普通夺门冲突和 AI 拒绝其他指令，记 4 分。

全片展示按名称给观众形成的预期、影片证据及该属性在本片中的重要性评分。常见题材和类型采用同一标准。与封闭标签的重复另行判断。人物标签达到 3–4 分，须能说明名称排除了哪些同类内容。

## 3. 评估调用与结果

### 3.1 调用方式

使用专门的「标签质量评估」提示词，由 LLM 对最终标签进行评价。每部影片默认将该影片进入待审核队列和直接挂载的全部标签放在一次请求中批量评估；只有在输入或输出长度超过模型限制时才分批处理。

评估模型应同时获得影片内容和最终标签信息，并为每个标签分别给出三个维度的评分及简短理由。内容相关性尽可能提供对应的场景或内容证据，方便前端查看。

评估提示词区分 `desc` 和 `reason` 的用途，要求模型只评估输入中的标签。现行开放评测使用 `open-review-v10`（`src/tagplatform/capabilities/prompts/open_review.py`）：按输入 `id` 对齐输出，每个条目返回 `relevance`、`semantics`、`value` 三维评分与理由、用于内容相关性取证的 `evidence_scene_ids`，以及综合后的保留结论 `keep` 与 `summary_reason`；场景级评分统一以标签的 `scene_ids` 定位来源场景，不回退挂载点 `target_id`。（早期生产附带评估使用 `tag-quality-v5`，证据字段为 `evidence`。）

### 3.2 影片级指标

每部影片计算并展示：

- 最终标签数量（包含待审核和直接挂载的标签）；
- 内容相关性平均分及各档分布；
- 语义准确性平均分及各档分布；
- 标签价值平均分、各档分布、满分率及覆盖情况；
- 内容相关性与语义准确性均为当前量表满分的标签比例（双维同时满分率）；
- 三个维度均为当前量表满分的标签比例（三维同时满分率）；
- 无法判断的数量及比例；
- 已完成评估的标签数量和评估覆盖率。

「无法判断」单独统计，不计入对应维度的平均分和满分率分母。系统调用失败或结果缺失属于评估未完成，不能记为「无法判断」或 0 分。

同时满分率的分母为对应维度均有数值评分的标签数。历史两维结果的标签价值显示「未评估」，并从标签价值评分及三维同时满分率的统计中排除。

### 3.3 任务级指标

将任务内所有影片的标签评估结果汇总，计算任务整体的：

- 内容相关性平均分及满分率；
- 语义准确性平均分及满分率；
- 标签价值平均分、满分率及覆盖情况；
- 双维和三维同时满分率；
- 最终标签总数、已评估数量和评估覆盖率；
- 影片总数、已完成评估影片数、评估中影片数和失败影片数。

任务级平均分和比例默认按标签汇总计算，使每个标签具有相同权重。任务内部分影片尚未完成评估时，展示当前汇总值和覆盖率，并标明结果尚未完整。

## 4. 前端展示

在现有「生产任务标签」页面中，用户展开一个生产任务时，增加「标签质量评估」区域。

展示分为三个层级：

**任务级汇总**

展示任务评估状态、影片完成情况、最终标签数量、评估覆盖率，以及三个维度的平均分、满分率和同时满分率。

**影片级结果**

任务内每部影片单独展示评估状态、标签数量、内容相关性、语义准确性、标签价值和同时满分率。各影片评估完成后即可展示，不需要等待整个任务全部评估结束。

**标签级结果**

在影片下展开标签列表，逐条展示：
- 最终标签名称和释义；
- 内容相关性评分及理由；
- 语义准确性评分及理由；
- 标签价值评分及理由；
- 内容相关性对应的场景或证据（模型能够提供时）。

标签列表默认紧凑展示评分；展开单条标签后查看详细理由和证据。

评估状态至少区分：等待评估、评估中、已完成、部分完成和评估失败。评估状态与现有人工审核状态分别展示，人工审核可以照常进行。

## 5. 状态与异常处理

- 每部影片的最终标签完成生产分流并保存后，创建或启动对应的评估子流程。
- 评估进度按影片独立更新，任务级指标随已完成结果更新。
- 某部影片评估失败时，其他影片继续处理；失败状态和原因在评估区域展示。
- 支持单独重试评估，重试时读取对应影片当前生成版本的最终标签快照，包含待审核和直接挂载的标签。
- 提示词版本变更后重试，按新口径重新评估该影片的全部快照标签。
- 记录评估所使用的模型和提示词版本，便于后续追踪结果。
- 如果影片没有生成任何最终标签，则该影片显示为无需评估，指标显示为空。

实现时沿用仓库现有任务调度、持久化和前端数据组织方式。评估数据与对应生产任务、影片及其待审核标签关联保存，以便任务详情直接读取和展示。
