# 生成标签自动质量评估功能

## 1. 功能位置与运行方式

在现有影视标签生产任务中增加「标签质量评估」环节。触发时机是：**某部影片的标签生成流程全部结束，最终标签完成生产分流之后**。生产分流包括进入待审核队列，以及满足条件后直接挂载；两类标签都参与评估。

执行流程：

1. 现有生成流程完成，产出该影片最终标签。
2. 标签按现有规则分流：需要人工审核的进入审核队列，满足条件的直接挂载。
3. 两类标签都进入本次质量评估范围，后台自动启动该影片的标签质量评估。
4. 评估完成后保存逐标签结果，并更新影片级指标和任务级汇总指标。

评估作为独立的后台子流程运行。生成任务完成、标签进入人工审核队列或直接挂载，以及人工审核操作，都不需要等待评估结束。评估状态单独记录和展示。

建议按影片触发评估：一部影片的最终标签完成生产分流后即可开始评估；任务内各影片的结果逐步完成，任务级指标随之更新。

评估针对**本次生产流程最终产出的标签结果快照**，同时包含进入人工审核队列的标签和满足条件直接挂载的标签。人工审核之后对待审核标签进行的通过、驳回或修改，仍按现有审核流程处理；评估结果对应的是生产分流时的那一版标签。

## 2. 评估输入与评价维度

### 2.1 输入内容

评估时使用该影片本次生成任务对应的影视内容，以及本次生产流程产出的最终标签，包括进入待审核队列和直接挂载的标签。

影视内容尽量沿用生成阶段已有的信息，包括影片摘要、人物、场景描述、台词和关键帧。标签侧使用最终标签名称、最终释义，以及现有数据中可用的层级和维度信息。

当前生成模板中：
- `desc` 是标签本身的通用释义，用于解释标签概念。
- `reason` 是生成模型给出的本片内容依据。

评估时，语义准确性主要依据标签名称及最终 `desc` 判断；内容相关性则应回到影片原始内容中寻找依据，不能仅凭生成模型提供的 `reason` 判定相关。

如果标签涉及画面风格、镜头语言等视觉信息，应尽量将生成阶段使用的关键帧一并提供给评估模型。缺少必要视觉材料时，允许将该项评为「无法判断」。

具体输入字段和数据映射以仓库中实际的待审核标签结构、影片内容结构为准，由实现时结合现有代码确定；本功能不另行定义生成结果的 JSON 格式。

### 2.2 内容相关性

评价问题：**这个标签所表达的概念，是否能从影片内容中找到依据？**

| 评分 | 标准 |
|---|---|
| 2 | 有明确、充分的内容依据，标签与影片内容高度吻合。 |
| 1 | 存在一定关联，但依据较弱、较间接，或内容只支持标签含义的一部分。 |
| 0 | 缺乏内容依据，或与影片内容明显矛盾。 |
| 无法判断 | 当前提供的文本或画面材料不足以判断。 |

评价时结合标签层级理解：全片级标签应由影片整体内容支撑；场景级标签可以由局部场景支撑。

### 2.3 语义准确性

评价问题：**标签名称及其释义，是否准确表达了一个明确、合理的概念？**

| 评分 | 标准 |
|---|---|
| 2 | 标签名称与释义一致，概念定义准确，语义边界合理。 |
| 1 | 基本表达了预期概念，但释义存在模糊、过宽、过窄或边界不清的问题。 |
| 0 | 概念理解或定义错误，名称与释义明显不一致，或对网络热梗、新兴概念存在实质性误用。 |
| 无法判断 | 缺乏足够语义背景，无法可靠确定该词的含义；或缺少最终释义，无法判断名称与释义是否一致。 |

### 2.4 标签价值

按标签层级评价名称是否适合预期用途。通用释义用于核对词义。

| 评分 | 全片展示 | 场景搜索 |
|---|---|---|
| 2 | 名称独立易懂，概括全片鲜明特征、主要冲突或关键看点。 | 名称自然具体、有区分度，用户可以据此找到目标场景或同类场景，例如「拆除定时炸弹」。 |
| 1 | 属性有辨识度，属于次要看点。 | 相关且可搜索，但较泛或带有不必要的限定。 |
| 0 | 表述生硬、过泛、依赖剧情上下文或只复述局部情节。 | 表述含糊、生硬、会匹配大量无关片段，或离开剧情上下文难以理解。 |
| 无法判断 | 材料不足以判断属性对全片展示的价值。 | 材料不足以判断能否帮助定位片段。 |

三维各自独立评分。场景级只在来源场景内核对相关性，局部动作或视听细节本身可以有较高检索价值。人物级按名称能否独立表达挂载人物的主要或次要属性评分。

## 3. 评估调用与结果

### 3.1 调用方式

使用专门的「标签质量评估」提示词，由 LLM 对最终标签进行评价。每部影片默认将该影片进入待审核队列和直接挂载的全部标签放在一次请求中批量评估；只有在输入或输出长度超过模型限制时才分批处理。

评估模型应同时获得影片内容和最终标签信息，并为每个标签分别给出三个维度的评分及简短理由。内容相关性尽可能提供对应的场景或内容证据，方便前端查看。

评估提示词区分 `desc` 和 `reason` 的用途，要求模型只评估输入中的标签。评估响应以快照标签的 `id` 对齐，`relevance`、`semantics` 和 `value` 分别包含 `score` 和评分理由 `reason`。内容相关性的证据放在 `evidence`。提示词标识为 `tag-quality-v3`，场景评分使用 `scene_ids` 定位生成证据，历史快照可回退到场景挂载点。

### 3.2 影片级指标

每部影片计算并展示：

- 最终标签数量（包含待审核和直接挂载的标签）；
- 内容相关性平均分及 0/1/2 分布；
- 语义准确性平均分及 0/1/2 分布；
- 标签价值平均分、0/1/2 分布、高分率及覆盖情况；
- 内容相关性与语义准确性均为 2 分的标签比例（双维联合合格率）；
- 三个维度均为 2 分的标签比例（三维联合合格率）；
- 无法判断的数量及比例；
- 已完成评估的标签数量和评估覆盖率。

「无法判断」单独统计，不计入对应维度的平均分和高分率分母。系统调用失败或结果缺失属于评估未完成，不能记为「无法判断」或 0 分。

联合合格率的分母为对应维度均有数值评分的标签数。历史两维结果的标签价值显示「未评估」，并从标签价值评分及三维联合合格率的统计中排除。

### 3.3 任务级指标

将任务内所有影片的标签评估结果汇总，计算任务整体的：

- 内容相关性平均分及高分率；
- 语义准确性平均分及高分率；
- 标签价值平均分、高分率及覆盖情况；
- 双维和三维联合合格率；
- 最终标签总数、已评估数量和评估覆盖率；
- 影片总数、已完成评估影片数、评估中影片数和失败影片数。

任务级平均分和比例默认按标签汇总计算，使每个标签具有相同权重。任务内部分影片尚未完成评估时，展示当前汇总值和覆盖率，并标明结果尚未完整。

## 4. 前端展示

在现有「生产任务标签」页面中，用户展开一个生产任务时，增加「标签质量评估」区域。

展示分为三个层级：

**任务级汇总**

展示任务评估状态、影片完成情况、最终标签数量、评估覆盖率，以及三个维度的平均分、高分率和联合合格率。

**影片级结果**

任务内每部影片单独展示评估状态、标签数量、内容相关性、语义准确性、标签价值和联合合格率。各影片评估完成后即可展示，不需要等待整个任务全部评估结束。

**标签级结果**

在影片下展开标签列表，逐条展示：
- 最终标签名称和释义；
- 内容相关性评分及理由；
- 语义准确性评分及理由；
- 标签价值评分及理由；
- 内容相关性对应的场景或证据（模型能够提供时）。

标签列表默认紧凑展示评分；展开单条标签后查看详细理由和证据。

评估状态至少区分：等待评估、评估中、已完成、部分完成和评估失败。评估状态与现有人工审核状态分别展示，人工审核可以照常进行。

## 5. 状态与异常处理

- 每部影片的最终标签完成生产分流并保存后，创建或启动对应的评估子流程。
- 评估进度按影片独立更新，任务级指标随已完成结果更新。
- 某部影片评估失败时，其他影片继续处理；失败状态和原因在评估区域展示。
- 支持单独重试评估，重试时读取对应影片当前生成版本的最终标签快照，包含待审核和直接挂载的标签。
- 提示词版本变更后重试，按新口径重新评估该影片的全部快照标签。
- 记录评估所使用的模型和提示词版本，便于后续追踪结果。
- 如果影片没有生成任何最终标签，则该影片显示为无需评估，指标显示为空。

实现时沿用仓库现有任务调度、持久化和前端数据组织方式。评估数据与对应生产任务、影片及其待审核标签关联保存，以便任务详情直接读取和展示。
