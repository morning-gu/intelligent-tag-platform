# 生成标签自动质量评估功能

> **现状说明**：原内嵌在「生产任务」中的附带标签质量评估已退役并迁入独立的**开放评测（Open Eval）**模块（详见 [`docs/eval.md`](eval.md) §5）。本文 **§2.2–§2.5 的三维 0–4 评分口径**现由 Judge 过滤与开放评测独立盲评提示词 `open-review-v12` 共用（统一标准定义于 `src/tagplatform/capabilities/prompts/_evaluation.py`，分别嵌入 `mtg.py` 与 `open_review.py`）；§1、§3.2–§5 记录的是早期生产任务附带评估的流程设计，留作历史参考。

## 1. 功能位置与运行方式（历史设计）

生产任务展开后，可在「标签产出与评分」卡片右上方打开「评分标准」，查看五档的判定门槛。

在现有影视标签生产任务中增加「标签质量评估」环节。触发时机是：**某部影片的标签生成流程全部结束，最终标签完成生产分流之后**。生产分流包括进入待审核队列，以及满足条件后直接挂载；两类标签都参与评估。

执行流程：

1. 现有生成流程完成，产出该影片最终标签。
2. 标签按现有规则分流：需要人工审核的进入审核队列，满足条件的直接挂载。
3. 两类标签都进入本次质量评估范围，后台自动启动该影片的标签质量评估。
4. 评估完成后保存逐标签结果，并更新影片级指标和任务级汇总指标。

评估作为独立的后台子流程运行。生成任务完成、标签进入人工审核队列或直接挂载，以及人工审核操作，都不需要等待评估结束。评估状态单独记录和展示。

建议按影片触发评估：一部影片的最终标签完成生产分流后即可开始评估；任务内各影片的结果逐步完成，任务级指标随之更新。

评估针对**本次生产流程最终产出的标签结果快照**，同时包含进入人工审核队列的标签和满足条件直接挂载的标签。人工审核之后对待审核标签进行的通过、驳回或修改，仍按现有审核流程处理；评估结果对应的是生产分流时的那一版标签。

## 2. 评估输入与评价维度

### 2.1 输入内容

评估时使用该影片本次生成任务对应的影视内容，以及本次生产流程产出的最终标签，包括进入待审核队列和直接挂载的标签。

影视内容尽量沿用生成阶段已有的信息，包括影片摘要、人物、场景描述、台词和关键帧。标签侧使用最终标签名称、最终释义，以及现有数据中可用的层级和维度信息。

当前生成模板中：
- `desc` 是标签本身的通用释义，用于解释标签概念。
- `reason` 是生成模型给出的本片内容依据。

评估时，语义准确性主要依据标签名称及最终 `desc` 判断；内容相关性则应回到影片原始内容中寻找依据，不能仅凭生成模型提供的 `reason` 判定相关。

如果标签涉及画面风格、镜头语言等视觉信息，应尽量将生成阶段使用的关键帧一并提供给评估模型。缺少必要视觉材料时，允许将该项评为「无法判断」。

具体输入字段和数据映射以仓库中实际的待审核标签结构、影片内容结构为准，由实现时结合现有代码确定；本功能不另行定义生成结果的 JSON 格式。

### 2.2 五档判定方式

现行 Judge 过滤与开放评测盲评提示词 `open-review-v12` 共用同一份统一三维评分标准（`src/tagplatform/capabilities/prompts/_evaluation.py`），对三个维度按 0–4 档评价。按 0 到 4 的顺序检查，命中第一档即停。`level` 决定取证范围（`film` / `scene`），`target_type` 决定标签种类（`content` 内容级 / `scene` 场景级 / `character` 人物级）。如果缺少必要材料或缺少释义且无法区分相邻档，记为 `null`；只要已有证据足以判断反证、目录不匹配或表述缺陷，就按对应低档评分。

### 2.3 内容相关性

检查名称的核心概念和每一个会改变含义的限定。场景词只用来源场景的材料。影片词的 3–4 分须有至少两个独立剧情或视听段落支撑。一个即时问题的发生、应对和解决合计一个事件，例如被困、找出口和脱困。相邻场景重复描述同一次转场时也只计一个段落。

| 分数 | 判定门槛 |
|---|---|
| 0 | 核心概念或任一必要限定有直接反证，或可核查材料中没有相关对象、事件与属性。 |
| 1 | 找得到相关对象、场所或话题，核心动作、属性或关系缺乏明确记录及可推导依据。 |
| 2 | 核心概念有明确依据，但缺少至少一个必要限定，或者全片级概括只由同一事件支撑。 |
| 3 | 核心与全部必要限定均能获证，覆盖范围符合层级，需要借材料中的细节完成一步推理。 |
| 4 | 核心与全部必要限定均能从场景描述、台词、画面或人物材料直接定位，覆盖范围符合层级。 |

### 2.4 语义准确性

融合评估三个方面：**名称清晰度**、**释义一致性**与**目标目录匹配度**。缺少通用释义致使无法核验释义一致性时记为 `null`，但仅凭名称或目标目录即可确认明显缺陷（不可解读、或核心含义明确不属于目标目录）时直接按对应低档评分。

| 分数 | 判定门槛 |
|---|---|
| 0 | 名称无法解读/自相矛盾；或名称与释义核心意思相反/无对应概念；或标签核心含义与目标目录定义明显不符、属于完全不同类别。 |
| 1 | 名称指代含糊；或名称与释义仅共享话题但中心指代/类别改变；或标签与目标目录仅间接联想，核心含义不属于该目录。 |
| 2 | 核心含义基本属于目标目录且中心概念成立，但名称边界模糊/有歧义、释义相对名称扩大/缩窄适用边界，或落在目录定义模糊边缘。 |
| 3 | 名称清晰无歧义、核心含义明确属于目标目录、名称与释义边界一致，但释义仅换词复述、含本片具体实例或区分条件不够清晰。 |
| 4 | 名称清晰自然、边界自明，核心含义精准契合目标目录定义，且通用释义与名称边界完全一致，给出了对象及可跨片判断的区分条件。 |

### 2.5 标签价值

标签价值只看标签名称独立传达的信息，不再按单维直出总分，而是由模型对以下三个方向分别打 **0–4 整数分**，再由程序按标签种类（内容级 `content` / 场景级 `scene` / 人物级 `character`）的权重加权聚合为保留两位小数的 0.00–4.00 价值分（统计 0–4 分档分布时四舍五入归档）：

1. **内容呈现（`presentation`）**
   - 内容（不代表“内容/全片标签”种类限定）：描述影视内容的主题、核心剧情及内容特色，实现内容的细粒度表达；
   - 场景（不代表“场景标签”种类限定）：描述剧情中的关键情节事件、典型桥段及名场面类型，突出内容的故事看点；
   - 角色（不代表“角色标签”种类限定）：描述角色的人设模板、人物性格，丰富角色画像。
2. **内容搜索（`search`）**
   - 类型：描述内容所属的题材、类型及细分主题，支持分类检索；
   - 风格：描述内容的叙事结构及价值导向，支持多维风格检索；
   - 情绪：描述内容传递给观众的情绪感受与氛围基调，支持用户基于情绪诉求检索。
3. **内容推荐（`recommendation`）**
   - 时间：描述内容适合的观影时间、地点及环境场景，回答【何时何地看】；
   - 强度：描述观看内容所需的注意力投入程度及认知负荷，匹配不同观看状态；
   - 人员：描述内容适合的社交观影语境及共同观看人群，回答【和谁一起看】。

默认三方向权重（顺序：`内容呈现 / 内容搜索 / 内容推荐`，支持 `TAGPLT_TAG_VALUE_WEIGHTS_{CONTENT,SCENE,CHARACTER}` 覆盖）：

| 标签种类 | 内容呈现 | 内容搜索 | 内容推荐 |
|---|---|---|---|
| 内容级（`content`） | 0.30 | 0.40 | 0.30 |
| 场景级（`scene`） | 0.50 | 0.40 | 0.10 |
| 人物级（`character`） | 0.55 | 0.30 | 0.15 |

## 3. 评估调用与结果

### 3.1 调用方式

使用专门的「标签质量评估」提示词，由 LLM 对最终标签进行评价。每部影片默认将该影片进入待审核队列和直接挂载的全部标签放在一次请求中批量评估；只有在输入或输出长度超过模型限制时才分批处理。

评估模型应同时获得影片内容和最终标签信息，并为每个标签分别给出三个维度的评分及简短理由。内容相关性尽可能提供对应的场景或内容证据，方便前端查看。

评估提示词区分 `desc` 和 `reason` 的用途，要求模型只评估输入中的标签。现行开放评测使用 `open-review-v12`（`src/tagplatform/capabilities/prompts/open_review.py`），与 Judge 共用统一三维评分标准：按输入 `id` 对齐输出，每个条目返回 `relevance`、`semantics`（融合名称清晰度、释义一致性与目录匹配度）、`value` 下内容呈现/内容搜索/内容推荐三方向评分与理由（由程序按 `target_type` 权重聚合为保留两位小数的 `value.score`）、用于内容相关性取证的 `evidence_scene_ids`，以及综合后的保留结论 `pass` 与总评 `reason`；场景级评分统一以标签的 `scene_ids` 定位来源场景，不回退挂载点 `target_id`。（早期生产附带评估使用 `tag-quality-v5`，证据字段为 `evidence`。）

### 3.2 影片级指标

每部影片计算并展示：

- 最终标签数量（包含待审核和直接挂载的标签）；
- 内容相关性平均分及各档分布；
- 语义准确性平均分及各档分布；
- 标签价值平均分、各档分布、满分率及覆盖情况；
- 内容相关性与语义准确性均为当前量表满分的标签比例（双维同时满分率）；
- 三个维度均为当前量表满分的标签比例（三维同时满分率）；
- 无法判断的数量及比例；
- 已完成评估的标签数量和评估覆盖率。

「无法判断」单独统计，不计入对应维度的平均分和满分率分母。系统调用失败或结果缺失属于评估未完成，不能记为「无法判断」或 0 分。

同时满分率的分母为对应维度均有数值评分的标签数。历史两维结果的标签价值显示「未评估」，并从标签价值评分及三维同时满分率的统计中排除。

### 3.3 任务级指标

将任务内所有影片的标签评估结果汇总，计算任务整体的：

- 内容相关性平均分及满分率；
- 语义准确性平均分及满分率；
- 标签价值平均分、满分率及覆盖情况；
- 双维和三维同时满分率；
- 最终标签总数、已评估数量和评估覆盖率；
- 影片总数、已完成评估影片数、评估中影片数和失败影片数。

任务级平均分和比例默认按标签汇总计算，使每个标签具有相同权重。任务内部分影片尚未完成评估时，展示当前汇总值和覆盖率，并标明结果尚未完整。

## 4. 前端展示

在现有「生产任务标签」页面中，用户展开一个生产任务时，增加「标签质量评估」区域。

展示分为三个层级：

**任务级汇总**

展示任务评估状态、影片完成情况、最终标签数量、评估覆盖率，以及三个维度的平均分、满分率和同时满分率。

**影片级结果**

任务内每部影片单独展示评估状态、标签数量、内容相关性、语义准确性、标签价值和同时满分率。各影片评估完成后即可展示，不需要等待整个任务全部评估结束。

**标签级结果**

在影片下展开标签列表，逐条展示：
- 最终标签名称和释义；
- 内容相关性评分及理由；
- 语义准确性评分及理由；
- 标签价值评分及理由；
- 内容相关性对应的场景或证据（模型能够提供时）。

标签列表默认紧凑展示评分；展开单条标签后查看详细理由和证据。

评估状态至少区分：等待评估、评估中、已完成、部分完成和评估失败。评估状态与现有人工审核状态分别展示，人工审核可以照常进行。

## 5. 状态与异常处理

- 每部影片的最终标签完成生产分流并保存后，创建或启动对应的评估子流程。
- 评估进度按影片独立更新，任务级指标随已完成结果更新。
- 某部影片评估失败时，其他影片继续处理；失败状态和原因在评估区域展示。
- 支持单独重试评估，重试时读取对应影片当前生成版本的最终标签快照，包含待审核和直接挂载的标签。
- 提示词版本变更后重试，按新口径重新评估该影片的全部快照标签。
- 记录评估所使用的模型和提示词版本，便于后续追踪结果。
- 如果影片没有生成任何最终标签，则该影片显示为无需评估，指标显示为空。

实现时沿用仓库现有任务调度、持久化和前端数据组织方式。评估数据与对应生产任务、影片及其待审核标签关联保存，以便任务详情直接读取和展示。
