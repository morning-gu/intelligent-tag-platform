# 闭环评测整体漏斗与漏斗 UI 升级设计（短文档）

日期：2026-11-26 · 状态：已批准（对话内拍板：位置=单片明细区顶部前端聚合；范围=整体+单片都升级）
前置：2026-11-26-closed-eval-funnel-design.md（funnel trace 已交付，PR #47）

## 意图

funnel trace 已落逐片数据；本轮补**全 run 聚合视图**（标签在管线五层的总损耗一眼可见）并把漏斗展示升级到开放评测报告的视觉档位（卡片/图表化）。

## 目标

- 「单片明细」区顶部新增**整体漏斗块**：全 run 各行 funnel 加总；
- 单片明细的文本漏斗条升级为 mini BarChart。

## 非目标

- 后端零改动（report.json/端点/schema 全不动——沿用上轮「报告零改动」非目标）；
- θ 门交互不动（漏斗与 θ 无关）；踪迹表/结局筛选/丢失环节列/下载不动。

## 方案（已选）

- 位置：单片明细区顶部（`ClosedEvalMovieTable`，θ 控件与主表之间），前端聚合 `payload.rows` 的 `funnel`——数据已在手，零后端改动。被否的备选：report.json 增聚合块（动上轮非目标、后端+前端都要改）、两处都出（最贵无增量）。
- 覆盖面：整体块 + 单片升级都做。

## 设计要点

- **聚合**（纯函数，组件内导出供测试）：只聚合 funnel 非 null 行（失败片无 trace 不计入）；块内标注「合计覆盖 N/总片数」；「门控过 = n_mentioned − n_gate」「挂载成 = 门控过 − n_unmountable」差式派生（与单片漏斗条同款，终审核实的分流完备口径）。
- **整体块形态**：`Statistic` 卡行五值（召回/提及/门控过/挂载成/产出）→ `BarChart` 五行漏斗条（max=召回总量）→ 次要计数一行（门控丢弃/挂载失败/截断/编造/批次含重试）→ 每片存活率（产出/召回）min/中位/max（召回为 0 的片跳过，全跳过 →「暂无」；开放报告「伴生指标」同款模式）。
- **单片漏斗条**：文本统计行换 mini BarChart（同 `BarChart` 组件，max=该片召回），次要计数文本行保留。
- **共用组件 `FunnelBars`**：接收 counts 的纯展示小组件，整体块与单片条共用。
- **老 run**：全部行 funnel=null → 整体块渲染说明文案（同单片 absent 口径，显式优于消失）。
- **视觉语言**：完全沿用仓库既有 `BarChart`（纯 CSS）+ `Statistic`（两份报告组件同款），不引入新图表库。
- None≠0「暂无」纪律、代际守卫/懒加载缓存逻辑不动、不新增请求（聚合在已拉回的 summary payload 上）。

## 任务草案（2 任务）

1. T1 整体漏斗块（FunnelBars 抽取 + 聚合/存活率纯函数 + Statistic 行 + BarChart + 次要计数 + 老暂无 + 测试）；
2. T2 单片漏斗条升级为 mini BarChart（复用 FunnelBars，次要计数保留）+ 测试。
