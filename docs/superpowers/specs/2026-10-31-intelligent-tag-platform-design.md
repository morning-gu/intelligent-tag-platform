# 影视智能标签平台——头脑风暴定稿设计

日期：2026-10-31
状态：已与项目负责人逐节确认，待实现规划
原始提案：`intelligent-tag-platform/docs/design.md`（本文档在其基础上记录全部已定决策与增量设计；未提及处仍以原始提案为准）

---

## 1. 背景与定位

本项目是影视标签研究的**工程化落地**：把研究中验证过的标签生成方法（封闭式提取 + 开放式生成）建成一个实际可用的离线标签生产平台。视频理解（VLM/ASR/OCR 识别）**不在本项目范围内**——已识别内容从其他专门做视频理解的项目迁移而来，本项目只聚焦标签系统本身。

- **使用者**：项目负责人 + 若干协作者，通过审核后台**多人协作**；角色分管理员（治理 + 配置）与审核员。
- **内容规模**：几十部影片/剧集，离线批量生产，非在线服务。
- **成功画面**：批量跑标签 → 审核后台能**看清模型为什么打了这个标签**（证据、视频位置、分数）→ 多人分工审核 → 入库形成正式标签资产。

### 1.1 目标

1. 统一内容 JSON 标准与外部转换层，吃进外部视频理解项目的识别结果。
2. Excel 标签库导入 + 自动治理流水线，形成正式标签库。
3. 两种标签生产模式（封闭提取 / 开放生成）批量打标，证据可追溯。
4. 多人协作审核后台：视频播放、场景时间轴、证据定位、审核入库。
5. 全程可追溯：批次号、审核记录、标签变更历史、模型与 Prompt 版本。

### 1.2 非目标（本期不做）

- 视频解析、抽帧、ASR/OCR/VLM 识别（模块一/二仅接口定义，见 §9）。
- 在线标签搜索服务（模块七仅接口定义）。
- 多模型供应商接入层。
- P/R/F1 等需要真值标注的质量指标。

### 1.3 反目标（出现即算失败）

- **代码增加流程不可扩展**：将来接新识别服务、加新生产模式需要改动主流程。
- **界面无法呈现标签识别效果**：审核员看不出标签为什么被打上、证据在哪。

两条反失败设计承诺见 §10，属硬性验收标准。

## 2. 已定决策汇总

| 决策点 | 结论 |
|---|---|
| 项目定位 | 研究成果落地工程平台，聚焦标签系统，识别结果外部迁移 |
| 内容入口 | 入口 B 为主（JSON 导入 + 转换层）；附简单上传占位（存文件 + 登记，无识别） |
| 模型层 | 完全沿用 MovieTagGen 栈：qwen3.7-plus（OpenAI 兼容 API）+ `intfloat/multilingual-e5-base` 本地向量；单模型，不做多供应商抽象 |

| 数据契约 | 平台自定义统一内容 JSON；外部来源写转换层适配 |
| 后端 | Python + FastAPI + SQLAlchemy；SQLite（WAL 模式）+ sqlite-vector 向量扩展 |
| 前端 | React + Ant Design SPA（前后端分离，前端单独构建） |
| 标签分组 | 分组 = `tag_type` 字段，不新增分组字段；召回按分组各自 top-k |
| 内容向量时机 | `media_context` 的向量在模式 A/B 任务处理时各自计算，导入时不预计算 |
| 标签向量时机 | `tag_catalog` 向量在 Excel 导入时计算 |
| 数据表 | 原方案 7 张 + 新增 `tag_change_log`，共 8 张 |
| 审核 | 轻量账号（管理员/审核员两角色）+ session 登录；乐观并发检查 |
| 质量指标 | 一期全部从审核记录推导；P/R/F1 二期 |
| 任务执行 | 进程内后台线程池 + 任务表状态机，不引入独立队列 |

| 模式 A 向量粒度 | 整片摘要向量 + 每场景描述向量并集召回（my call，可推翻） |

## 3. 统一内容 JSON 标准（模块三数据契约）

Schema v1.0，字段结构沿用原始提案 §3.3.1：`asset`（asset_id / asset_type / title / duration_ms / video_uri，剧集-影片-场景层级用 `asset_type` + `parent_id` 表达）、`content`（summary + scenes 数组，每场景含 time_range、description、visual_features、dialogues、entities、events）、`metadata`（source / model_version / recognition_status）。大文件只存 URI。

`schema_version` 管理格式演进。场景与台词保留毫秒时间戳，是标签证据追溯的基础。

**转换层（外部内容适配）**：平台定义 `ContentAdapter` 适配器接口（见 §9），本期实现一个针对外部视频理解项目输出格式的适配器，负责字段映射、层级组装、时间戳单位归一。新来源 = 新适配器实现 + 注册。已确认来源输出含场景级起止时间戳，§10 证据时间轴与跳转播放的验收前提成立。

## 4. 数据库设计（模块六）

8 张表，SQLite + sqlite-vector（向量存 BLOB 列）。在原始提案 §3.6 基础上的增量：

1. **新增 `tag_change_log`**：tag_id、动作（create/update/merge/deprecate/import）、变更前后值（JSON）、操作人、时间。满足"标签版本管理"的追溯要求（`review_record` 只覆盖审核操作，覆盖不了标签库管理页的直接编辑和治理合并）。
2. **`asset_tag` 唯一约束**：(asset_id, tag_id) 唯一；候选标签 (asset_id, candidate_name) 唯一。同一影片重跑生成任务时：**已 approved 的记录保留不动**（沿用原证据与评分）；pending 记录被最新结果覆盖；本次新出现的标签作为新 pending 插入。既保护审核成果，也避免审核列表随重跑膨胀。
3. **`review_status` 枚举四态**：pending / approved / rejected / merged。"修改"操作 = 修正字段后回到 pending，历史在 `review_record`。
4. `media_context.embedding` 保留列，值由生产任务写入（最近一次计算的向量，供调试与复用）；导入流程不碰模型。
5. `tag_catalog.embedding` 由 Excel 导入流水线计算（对 tag_name + description 拼接文本过 e5 模型）。

其余表结构与精简原则（别名 JSON 数组、证据 JSON、向量入主表）按原始提案 §3.6.2–3.6.4 执行。

## 5. 标签生产引擎（模块三）

两种模式共用统一内容 JSON 与上下文组装。`generation_policy`（target_scope、max_tags、min_confidence）由前端任务创建表单传入。标签一律挂影片级，场景仅作为证据出现；`target_scope` 保留字段以兼容未来场景级打标，一期前端只暴露影片级（表结构已支持场景级，将来打开不需改表）。

### 5.1 模式 A：封闭式标签提取

1. **按分组召回**：整片摘要 1 个向量 + 每场景描述各 1 个向量（均在 e5-base 512 token 限制内；场景向量任务内现算不落库，`media_context.embedding` 存整片摘要向量供调试复用——my call），在 `tag_catalog` 向量上取两类命中的并集去重，**按 tag_type 分组分别 top-k**（每组 k≈50，保证各分组覆盖均衡，防止单一大类刷屏）。
2. 候选标签（tag_id、tag_name、description）注入 Prompt，LLM 逐个判断与内容的相关性。
3. 输出 tag_id + relevance_score + confidence + evidence（引用 scene_id 与时间戳）。
4. 按 `min_confidence` 过滤后写入 `asset_tag`（origin=catalog，review_status=pending）。

### 5.2 模式 B：开放式标签生成

1. 统一内容 JSON 直接注入 Prompt，LLM 自由生成候选标签（名称 / 类型 / 定义 / 证据）。
2. 生成标签文本向量化，与 `tag_catalog` 做相似度匹配（阈值默认 0.85，可配置）。
3. 匹配上映射到已有 tag_id（origin=catalog）；未匹配上的作为新标签候选（tag_id 为空，保存 candidate_name/type/description）。
4. 全部写入 `asset_tag` 待审核。新标签只有经审核"通过/合并"后才进入正式标签库。

模式 B 的去重归一在实现上直接调用模块四的语义匹配服务（单体内部即服务调用，模块边界是逻辑的）。

### 5.3 共用机制

- **Prompt 外置**：模式 A/B 各一套模板，存 DB 带版本号，后台可编辑；`generation_task` 记录当次使用的 model_version + prompt_version。
- **任务执行**：进程内后台线程池；`generation_task` 状态机 queued → running → succeeded / failed；失败支持手动重试。
- **upsert 语义**：同一 (asset, tag) 重复生成时覆盖旧结果（见 §4.2）。

## 6. 标签治理（模块四）

Excel 导入支持层级模板：一级标签名称、二级标签名称、三级标签名称、标签、
标签描述、标签生成方式六列。一级标签名称、二级标签名称、标签、标签描述必填；
三级标签名称可空，空时标签挂在二级标签名称下；导入后的 tag_type 固定为
genre；标签生成方式为空时 TagRow.is_manual 为 true，否则为 false。
同时兼容旧版 8 字段模板（tag_id 可系统生成；tag_name / tag_type /
description 必填；parent_tag / aliases / applicable_scope / status 选填）。

导入流水线：解析 → 字段校验 → 精确重复检测（名称/别名冲突）→ 语义相似检测（tag_name + description 向量，相似度 ≥0.9 判疑似同义，进待处理列表）→ 层级校验（parent 存在、无循环依赖）→ 分类合法性校验 → 无冲突自动入库、有冲突人工处理。全程记录批次号，写入 `import_batch`；标签库变更写 `tag_change_log`。

## 7. 审核后台（模块五）

8 个页面按原始提案 §3.5.1：工作台、标签库管理、标签导入管理、标签生产任务、标签审核中心、内容详情、质量评估中心、模型配置中心。

### 7.1 账号与并发

- 轻量账号表：用户名 + 密码哈希 + 角色（admin / reviewer），session 登录。
- 审核操作（通过 / 拒绝 / 修改 / 合并）写 `review_record`，reviewer_id 关联真实用户。
- 乐观并发检查：提交时若目标记录已被他人处理，提示冲突并刷新，不静默覆盖。

### 7.2 视频证据查看

- 后端以 HTTP range 请求提供本地视频文件（NAS 挂载目录或本地磁盘）的流式播放。已确认部署服务器可直接访问视频文件；内容导入时登记 video_uri 与服务器实际路径的映射规则（如统一根目录 + 相对路径前缀映射）。
- 内容详情页：场景时间轴条带（按 time_range 铺开），场景下挂标签。
- 标签证据卡：展开显示证据列表（场景片段 + 描述 + 台词摘录），点时间戳**跳转视频播放到该位置**。

### 7.3 质量指标（一期）

全部从审核记录与任务表推导：标签通过率、拒绝率、人工修正率、新标签审核通过率、证据覆盖率（有证据的标签占比）、任务成功率 / 耗时 / 失败率。P/R/F1 等到有真值标注后二期再加。

## 8. 模型配置与运营（模块八）

- 模型配置中心 = 配置存储 + 编辑：LLM 模型名与采样参数、embedding 模型、Prompt 模板（带版本，模式 A/B 各一套）。
- 任务监控：任务列表、状态、耗时、失败重试。
- 上传占位：简单上传表单 → 存文件 → 登记 `media_asset`（video_uri），不做识别。
- 部署：与 MovieTagGen 同服务器，Docker Compose 起服务；SQLite 数据文件与视频目录挂卷。

## 9. 可扩展性设计（反失败承诺一）

架构强制以下扩展点，验收标准是"新增扩展点实现不改主流程"：

1. **内容接入适配器**：`ContentAdapter` 接口（Python Protocol）+ 注册机制。模块一/二/七的预留 API 在路由层定义、内部抛 NOT_IMPLEMENTED 或走适配器分发；本期转换层是第一个实现。
2. **标签生产器注册**：模式 A/B 是同一 `TagProducer` 接口下的两个实现，任务创建按 mode 分发；新增模式 = 新实现类 + 注册，任务调度、审核流程、前端筛选自动兼容。
3. **Prompt 外置**：改提示词零代码变更。
4. **分层**：核心打标 / 治理逻辑为纯 Python 包（不依赖 FastAPI），API 层与前端只做编排；研究代码可直接 import 服务层。

## 10. 界面呈现识别效果（反失败承诺二）

审核后台的硬性验收标准：**审核员不用看代码就能回答"模型为什么打了这个标签"**。以下为必备能力：

1. 内容详情页场景时间轴条带 + 标签反向高亮场景。
2. 标签证据卡 + 时间戳跳转视频位置（§7.2）。
3. 置信度 / 相关性分布视图：快速圈出模型不确定的分数区间集中审核。
4. 按 tag_type 分组的标签覆盖视图：一眼看出哪类标签缺失（呼应按分组召回）。
5. 审核列表支持按置信度、tag_type、来源模式筛选与批量操作。

## 11. 交付阶段

| 阶段 | 内容 | 交付物 |
|---|---|---|
| 1 | 内容 JSON 标准 + 外部转换层适配器、SQLite 8 表、Excel 导入 + 治理流水线 | 可导入标签库和已识别内容 |
| 2 | 模式 A（按分组召回）/ 模式 B 生产引擎、Prompt 初版、批量打标跑通 | 标签生产引擎 |
| 3 | 审核后台 8 页面 + 账号登录、视频播放与证据定位、质量指标（推导版）、入库闭环 | 完整多人审核闭环 |
| 4 | 模型配置中心 + Prompt 版本管理、任务监控/重试、上传占位 | 运营完善 |

## 12. 留给实现者的决定

- 具体的 SQLite 向量扩展选型与集成方式（sqliteai/sqlite-vector 或 sqlite-vec，以能在当前环境跑通为准）。
- ORM 细节、迁移工具（如 Alembic）、前端路由与状态管理选型。
- 每组召回 top-k、相似度阈值等参数的默认值（文中数值为起点，须做成可配置）。
- 账号 session 的具体实现（cookie session 或 JWT 均可，够轻就行）。
- 8 张表的最终 DDL 细节（索引、外键策略）。
- 内容 JSON 导入入口形态（页面上传单文件/批量、目录约定）、账号初始化与首个管理员的创建流程。
- 阶段内任务拆分与测试策略。
