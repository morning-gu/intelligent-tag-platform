# 在线 X-MLClass 与 `mtg-v3` 对照方案

两套算法独立生成，共用提供给 LLM 的全片文本、关键帧、初始标签和目录提示。基准对双方的排序结果执行同一套语义去重，再截取前 K 条，最后按同一评估口径比较效果与成本。

## 1. 两套方案

| 方案 | 生成流程 |
| --- | --- |
| **A · `mtg-v3`** | 使用现有实现。全片文本和关键帧独立生成三轮，按原流程合并、judge、对齐和排序。 |
| **B · 在线 X-MLClass** | 按场景召回和打分，从低覆盖场景提词并在线更新词表，再用更新后的词表给场景打分、聚合成影片标签。 |

MTG-v3 保留内部跨轮合并和 judge，X-MLClass 通过场景召回、NLI 和排名投票得出影片标签。两套算法各自保存词表状态和结果。 [现有 `mtg-v3` 流程](./dynamic_label_gen.md) · [X-MLClass 论文分析](./x-mlclass-paper-analysis.md)

## 2. B 组单片流程

1. **场景打分。** 直接用现有标签库初始化工作词表。每个场景用向量召回少量标签，再用 NLI 判断场景文本是否支持标签，保留支持分和场景 ID。低覆盖排序使用各标签独立的支持分，避免候选集合变化影响分数的可比性。
2. **低覆盖提词。** 从最高支持分偏低且有可用内容的场景中选少量片段。模型读取共享影片材料，按场景 ID 提取关键词并引用该场景原文。
3. **累积并扩词。** 对库外词先归一化，再按需比对候选池里的代表词。确认同义时合并影片记录，同一部影片只计一次。候选词在本片有校验通过的来源记录，就能参与本片评分。默认达到两部影片且与词表查重通过后，才加入共享工作词表。
4. **重打分并输出。** 本片有待累计的新词或本轮有新词入表时，重打分一次。按场景标签排名聚合出影片标签，并保留支持场景。统一去重时先按名称归一化，再让模型复核向量筛出的相似标签对。同一评测实例的后续任务继承已保存的共享词表和候选池。

原论文用 GMM 构建初始词表，补词阶段直接更新词表并重跑打分。B 已有初始标签库，可以跳过 GMM。实验保留按场景打分、低覆盖补词和重打分这条主线。 [X-MLClass 论文 §5](https://aclanthology.org/2024.emnlp-main.841.pdf) · [作者的扩词脚本](https://raw.githubusercontent.com/Kaylee0501/X-MLClass/main/OpenWordMLTC/self_training/self_training.py)

## 3. 改造与快速验证步骤

1. **分别创建两组批次。** 在各自实例选择相同的影片、片序、初始词表、标签上限和评估提示词。各组保存自己的影片输入、标签、场景证据、耗时和 token。 [独立运行说明](x-mlclass-online.md)
2. **查看各组独立评估结果。** 用同一评估模型判断每条标签的展示价值，比较逐片去重后的可展示概念数、可展示占比和运行成本。

如果 B 能产出更多可展示概念且成本可接受，再考虑接入正式生成入口。真实召回率需要独立参考集。
