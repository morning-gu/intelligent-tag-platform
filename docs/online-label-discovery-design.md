# 在线 X-MLClass 与 `mtg-v3` 对照方案

首轮直接比较两套完整生成算法。A 跑原版 `mtg-v3`。B 从同样的影片内容和初始标签库出发，由在线 X-MLClass 独立产出标签。两组各自完成生成和筛选，再用同一套自动评估比较效果与成本。

## 1. 两套方案

| 方案 | 生成流程 |
| --- | --- |
| **A · `mtg-v3`** | 使用现有实现。全片文本和关键帧独立生成三轮，按原流程合并、judge、对齐和排序。 |
| **B · 在线 X-MLClass** | 按场景召回和打分，从低覆盖场景提词并在线更新词表，再用更新后的词表给场景打分、聚合成影片标签。 |

B 独立运行，不调用 A 的三轮生成、跨轮合并和专用 judge。两组共用影片输入、初始标签库和结果格式。原版 `mtg-v3` 保留为基线，实验词表和结果单独保存。Open-Tag 的相似作品标签召回留作后续独立议题。 [现有 `mtg-v3` 流程](./dynamic_label_gen.md) · [X-MLClass 论文分析](./x-mlclass-paper-analysis.md) · [Open-Tag 论文分析](./open-tag-paper-analysis.md)

## 2. B 组单片流程

1. **场景打分。** 直接用现有标签库初始化工作词表。每个场景用向量召回少量标签，再用 NLI 判断场景文本是否支持标签，保留支持分和场景 ID。低覆盖排序使用各标签独立的支持分，避免候选集合变化影响分数的可比性。
2. **低覆盖提词。** 从最高支持分偏低且有可用内容的场景中选少量片段，让模型独立提取关键词，保留原词和来源场景。
3. **累积并扩词。** 对库外词先归一化，再按需比对候选池里的代表词。确认同义时合并支持文档，同一部影片只计一次。达到支持门槛且与词表查重通过的候选加入实验词表，未达门槛的留到后续影片继续积累。首版只做候选词级归并。
4. **重打分并输出。** 本片有新词加入时，用更新后的词表重打分一次。按场景标签排名聚合出影片标签，并保留支持场景。下一部片从上次的实验词表和候选池继续。

原论文用 GMM 构建初始词表，补词阶段直接更新词表并重跑打分。B 已有初始标签库，可以跳过 GMM。实验保留按场景打分、低覆盖补词和重打分这条主线。 [X-MLClass 论文 §5](https://aclanthology.org/2024.emnlp-main.841.pdf) · [作者的扩词脚本](https://raw.githubusercontent.com/Kaylee0501/X-MLClass/main/OpenWordMLTC/self_training/self_training.py)

## 3. 改造与快速验证步骤

1. **保存 A 的基线结果。** 建议先用 5–10 部影片，原样跑一遍 `mtg-v3`，保存每片最终标签和证据，附上耗时和 token。无需逐片 Ground Truth、人工盲审或评估页面。 [现有生成入口](../src/tagplatform/generation/mtg/pipeline.py#L272)
2. **实现 B 并回放同一批影片。** 从同一份初始词表按固定片序运行 B，输出同样的标签与证据字段。场景向量计算可以复用现有嵌入器，保留各场景的分数。两组统一最终标签数上限，各自沿用自己的内部流程。 [现有向量召回](../src/tagplatform/generation/recall.py#L38)
3. **做一次零人工对照。** 隐藏方案来源，将同一影片的标签与证据交给独立评估模型。主看两项：**去重后有本片证据且提供独立信息的标签数**，以及**证据不支持的标签比例**。同时记录耗时和 token，列出两组各自独有的标签及模型判定理由。

这一轮比较的是两套算法整体表现。若 B 能产出更多有证据的独立概念，错误比例和成本也可接受，再考虑接入正式生成入口。自动对照用于判断初步收益，真实召回率待有独立参考集时再测。
