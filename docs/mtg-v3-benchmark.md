# mtg-v3 基准使用说明

登录后进入「算法基准」(`/benchmarks`)，选择已有识别内容的影片（建议 5–10 部），设置统一标签上限，点击「生成并自动评估」。每片 mtg-v3 生成完成后自动使用固定的 `glm-5.3-flash` 评估，页面和创建 API 均不提供模型切换。页面每五秒刷新，分别展示生成中、独立评估中、完成及失败；展开影片行查看标签、场景时间区间、证据、评估理由和改写建议，导出按钮保存完整 JSON。

服务需配置真实 LLM、可用嵌入器、标签库和关键帧路径，且 `mtg_runs=3`。评估模型通过现有 LLM 服务地址与凭据调用，模型名必须不同于生成模型与内部 judge。未新增环境变量或数据库迁移。

「本次评估提示词」默认显示服务内置提示词，可在提交前编辑或恢复默认。自定义提示词随批次快照保存，系统附加固定的三类判定输出格式。批次提交后，编辑框恢复默认。已结束的批次可在卡片上确认删除，删除后无法从页面恢复。需要留档时可先导出快照。

评估复用现有 MaaS 网关 key，模型 ID 为 `glm-5.3-flash`。不改变 mtg-v3 生成模型或内部 judge；本功能接入算法基准页面，普通生产任务流程保持原样。

基准直接调用原 mtg-v3 流水线，不进入审核/正式标签持久化。原算法内部有新词与库内词两个桶，可能超过单桶上限；基准在原输出顺序上统一截取前 K 条，原产出数量和完整审计仍保存。后续算法应复用这一输出上限和评估函数。

每批保存固定影片顺序、原始内容 JSON、初始目录与标签库快照、算法参数、完整生成审计及结果。当前批次使用同一份只读词表对象。关键帧文件仍通过原路径读取，未复制图片；回放前需保证媒体文件不变。快照在 `mtg_report_dir/benchmarks` 下，应随审计目录一起持久化。页面导出的 JSON 包含输入内容，适合留档及后续 B 组回放。

当前口径为 `viewer-quality-v3`，评估标签能否独立读懂、是否能帮助观众理解或选择影片。模型看到影片内容和标签原词，逐条给出可直接展示、建议改写或不建议展示，并说明理由。改写建议仅供查看。mtg-v3 的内部 judge 继续负责证据审核。

- 可展示概念数：可直接展示的标签按同义概念逐片去重。
- 可展示占比：可展示概念数除以实际评估标签数。批次按标签数加权，无标签时显示 —。
- 每片可展示概念数：已评估影片的去重概念总数除以已评估影片数。空输出计入影片分母，评估失败不计入。
- 生成和独立评估分别记录耗时与 token。评估响应缺项、重复 ID 或格式错误时标为失败，保留生成结果及已有成本。零标签无需调用模型。

历史报告沿用原有证据口径。跨算法比较应固定评估版本、模型、影片输入和标签上限。
批次逐片运行，失败继续下一片，任一影片失败则批次标 failed；重启时未结束批次标失败，可重新创建，保留旧结果。当前使用应用后台任务，按项目现有单进程服务方式运行；不提供跨进程队列恢复。

本轮仅实现 A 组与通用评测基础。X-MLClass、跨方案独有标签对比、真实召回率留待用户检查后新分支实施。本次按要求未执行测试、构建或部署验证。

## 静态复查补充

- 基准显式传入应用配置，避免配置校验、报告目录与流水线实际读取值不同。原算法默认策略保持不变，仅在生成完成后应用评测上限。
- 基准创建要求真实嵌入器、三轮生成、启用 judge 和标签库。快照增加生成模型、温度、嵌入模型、词表版本和评估口径版本。
- 列表轮询只返回展示字段；导出时单独读取完整快照。批次汇总按报告保存的评估口径展示，失败影片不计入质量指标。
- 评估模型返回后，即使 JSON 校验失败，也保留原始输出、usage 和耗时；页面展示失败评估的已知成本。调用未返回 usage 时显示未知。
- 生成中途失败会保留耗时和可读取的部分审计；其完整 token 总数可能无法获取，页面留空，不计入已记录 token 汇总。成功生成的 token 仍是服务报告值，底层缺失 usage 或传输层重试产生的额外费用不保证完整，不能当作账单。
- 损坏的历史 JSON 会记录日志并跳过，不阻断其他报告读取。重启中断与单片失败均可在页面看到；失败后重新创建批次，不覆盖旧快照。
- 独立评估依据影片内容文本与标签原词，纯视觉信息可能被低估。生成仍使用原 mtg-v3 的关键帧输入。
